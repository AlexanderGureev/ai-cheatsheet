# Исследования и замеры

Шпаргалка для ответов на вопросы. Цифры с экрана — в первой таблице, остальное — запас для обсуждения.

## На экране

| Тезис | Что измерили | Источник |
|---|---|---|
| AI — усилитель процесса | ~5000 инженеров, 90% используют AI. AI усиливает и сильные, и слабые стороны команды. Одна из семи практик, которые усиливают пользу AI, — работа маленькими порциями. | [DORA 2025](https://blog.google/technology/developers/dora-report-2025/), [AI Capabilities Model](https://services.google.com/fh/files/misc/2025_dora_ai_capabilities_model.pdf) |
| План перед кодом | SWE-bench Verified, агент в Claude Code. Без плана 42,8%, агент сам пишет план — 48,2%, план от Claude Sonnet 4.5 — 57,8% (+15 п.п., ≈ +35%; в статье подано как «+15%»). План — короткий, пошаговый, до 8 шагов, без изменений кода. Исполнитель — Qwen3-Coder-30B; с сильными исполнителями эффект, вероятно, меньше. Opus 4.5 как планировщик дал меньше (54–56%): по выводу авторов, согласованность планировщика с исполнителем важнее силы модели. | [DCAS, Thangarajah et al., ASE 2026](https://arxiv.org/abs/2608.06113) |
| Требования одним промтом | 200 000+ симулированных диалогов с топовыми моделями. Когда требования приходят по частям, качество падает в среднем на 39%. Сбившись на раннем шаге, модель не возвращается на верный путь. | [LLMs Get Lost In Multi-Turn Conversation, ICLR 2026](https://arxiv.org/abs/2505.06120) |
| Короткий промт | 500 инструкций в одном запросе: лучшая модель выполняет 68%. Чем больше инструкций, тем больше пропусков. Ранние инструкции выполняются лучше поздних. | [IFScale, NeurIPS 2025](https://arxiv.org/abs/2507.11538) |
| Новая задача — новый чат | 18 моделей: качество падает с ростом контекста даже на простых задачах. | [Chroma, Context Rot, 2025](https://research.trychroma.com/context-rot) |
| Ревью всегда | 470 PR: в PR, написанных с AI, в 1,7 раза больше проблем. Ошибок логики больше на 75%, проблем безопасности — до 2,74 раза. | [CodeRabbit, Dec 2025](https://coderabbit.ai/blog/state-of-ai-vs-human-code-generation-report) |
| Безопасность — построчно | 80 задач, 100+ моделей, замеры с 2023 по 2026 год. Проверку безопасности проходит 55–56% кода, то есть в ~45% случаев код содержит уязвимость. Синтаксис за это время вырос с ~50% до 95%, а безопасность не сдвинулась. Летом 2026 проверили 11 новых моделей: лучшая (GPT-5.5) — 68%, шесть из 11 — 50–53%. Reasoning-модели OpenAI из весеннего отчёта — 70–72%, то есть 68% — лучший результат только среди летних моделей. Задачи подобраны так, чтобы в них можно было допустить уязвимость (SQL-инъекции, XSS, log injection, слабая криптография), поэтому 45% — не доля всего AI-кода. | [Veracode, 2026](https://www.veracode.com/blog/2026-genai-code-security-report), [Spring 2026 Update](https://www.veracode.com/blog/spring-2026-genai-code-security) |
| Линтер как обратная связь | GPT-4o исправлял код по замечаниям статических анализаторов (Bandit, Pylint), до 10 итераций. Проблем безопасности стало 13% вместо >40%, нарушений читаемости — 11% вместо >80%, проблем надёжности — 11% вместо >50%. | [Static Analysis as a Feedback Loop, 2025](https://arxiv.org/abs/2508.14419) |
| Архитектура: запутанный код | Рецензируемое исследование: в коде с низким Code Health AI-изменения повышают риск дефектов минимум на 30%. | [Borg & Tornhill, CodeScene, 2026](https://www.prnewswire.com/news-releases/ai-coding-assistants-increase-defect-risk-by-30-in-unhealthy-code-new-peer-reviewed-research-finds-302672355.html) |
| Архитектура деградирует с объёмом | Объём кода почти идеально предсказывает структурную деградацию. Ни корректность, ни подробный промт её не предотвращают. Чем сильнее модель, тем более раздутый и связанный код она пишет. Вывод авторов: проблема не в генерации кода, а в управлении архитектурной сложностью, агентам нужно «архитектурное предвидение». Варианты с архитектурным контролем авторы не проверяли. | [Zhu, Tsantalis, Rigby, Concordia, 2026](https://arxiv.org/abs/2605.02741) |
| Логирование | 4550 PR от агентов в 81 репозитории. В 58,4% репозиториев агенты трогают логи реже людей. Явные просьбы про логи встречаются редко (4,7%) и в 67% случаев не выполняются. 72,5% исправлений логов делают люди. Вывод авторов: текстовых инструкций мало, нужны автоматические проверки. | [Ouatiti et al., 2026](https://arxiv.org/abs/2604.09409) |
| Обработка ошибок | В PR с AI пробелы в обработке ошибок встречаются почти в 2 раза чаще. | [CodeRabbit, Dec 2025](https://coderabbit.ai/blog/state-of-ai-vs-human-code-generation-report) |
| Авторевью сокращает цикл | RovoDev Code Reviewer: 1900+ репозиториев, год работы. Медианное время PR −30,8%, ручных комментариев −35,6%, 38,7% AI-замечаний привели к изменению кода. Устроен в три этапа: генерация замечаний, LLM-судья проверяет факты, классификатор отсеивает неполезное. | [Atlassian, ICSE 2026](https://arxiv.org/abs/2601.01129) |
| Двухэтапное ревью | BitsAI-CR: RuleChecker ищет нарушения по таксономии правил, ReviewFilter перепроверяет. Точность 75%, 12 000+ пользователей в неделю. | [ByteDance, 2025](https://arxiv.org/abs/2501.15134) |
| Риск авторевью — шум | 238 разработчиков, 4335 PR: 73,8% AI-замечаний исправили, но среднее время закрытия PR выросло с 5 ч 52 мин до 8 ч 20 мин. Среди причин — ошибочные, лишние и нерелевантные замечания. | [Automated Code Review In Practice, ICSE SEIP 2025](https://arxiv.org/abs/2412.18531) |
| Опыт | 791 разработчик. Больше половины кода в проде написано AI у 32% сеньоров (10+ лет) и у 13% джунов (0–2 года). Около 30% сеньоров правят AI-код так часто, что это съедает бо́льшую часть выигрыша; у джунов таких 17%. | [Fastly, 2025](https://www.fastly.com/blog/senior-developers-ship-more-ai-code) |
| `AGENTS.md` | 10 репозиториев, 124 PR, Codex и Claude Code. С `AGENTS.md` медианное время работы −28,6%, выходные токены −16,6%. | [Lulla et al., 2026](https://arxiv.org/abs/2601.20404) |
| `AGENTS.md` пишем сами | Написанный вручную: +4% решённых задач. Сгенерированный моделью: −3% и +20% к стоимости. Обзор структуры проекта не ускорил поиск нужных файлов. | [Gloaguen et al., ETH Zürich, 2026](https://www.sri.inf.ethz.ch/publications/gloaguen2026agentsmd) |
| AI ускоряет и новичков, и опытных | Внедрение Claude Code и Copilot CLI в Microsoft, начало 2026, десятки тысяч инженеров: +24% смёрженных PR (95% CI +14,5…+33,7%), эффект держится 4 месяца. У джунов (IC2–IC3) прирост больше, чем у мидлов (IC4, +21,3%). По стажу — буква «C»: у новичков и у тех, кто работает 15+ лет, прирост больше, чем при стаже 5–15 лет (+21,5%). Не RCT: синтетический контроль + сравнение с собой; качество кода не мерили. Раньше: три RCT с Copilot, 4000+ разработчиков, +26% задач в неделю. | [Murphy-Hill et al., 2026](https://arxiv.org/abs/2607.01418), [Cui et al., Management Science, 2026](https://doi.org/10.1287/mnsc.2025.00535) |

## В запасе

- **Самопроверка модели.** Без внешней обратной связи самопроверка не улучшает ответ модели, а иногда ухудшает.
  Исследование 2023 года на задачах рассуждения, новые модели проверяют себя лучше.
  [Huang et al., Google DeepMind, ICLR 2024](https://arxiv.org/abs/2310.01798)
- **Модели любят свои ответы.** Модели узнают свои ответы и оценивают их выше чужих — довод за ревью другой
  моделью. [Panickssery et al., NeurIPS 2024](https://arxiv.org/abs/2404.13076)
- **Google AutoCommenter.** LLM проверяет код на соответствие лучшим практикам команды у десятков тысяч
  разработчиков. Каждое замечание ссылается на документ с правилом, а ревьюеры-люди освобождаются для проверки
  логики. [Google, 2024](https://research.google/pubs/ai-assisted-assessment-of-coding-practices-in-industrial-code-review/)
- **Перекритика.** LLM-ревьюеры часто признают корректный код несоответствующим требованиям. Просьба объяснить
  и предложить исправление увеличивает число ошибок. Авторы предлагают проверять предложенные исправления
  тестами. [Jin & Chen, 2026](https://arxiv.org/abs/2603.00539)
- **Примеры в промте ревьюера.** Для автоматизации ревью few-shot (примеры в промте) работает лучше, чем
  zero-shot (без примеров). [Pornprasit & Tantithamthavorn, 2024](https://arxiv.org/abs/2402.00905)
- **Модели зрелости.** Единой модели нет. Похожие лестницы: пять уровней Дэна Шапиро — от автодополнения до
  «тёмной фабрики» ([Simon Willison](https://simonwillison.net/2026/Jan/28/the-five-levels/)), и AI Codebase
  Maturity Model. Главная мысль ACMM: интеллект AI-системы разработки — не в модели, а в инфраструктуре
  инструкций, тестов, метрик и обратной связи. [Anderson, 2026](https://arxiv.org/abs/2604.09388)

- **Меньше переиспользования.** GitClear проанализировал 211 млн изменённых строк. Доля перемещённого кода
  (признак рефакторинга) упала ниже 10%, а дублирующихся блоков в 2024 году стало в 8 раз больше.
  [GitClear, 2025](https://devclass.com/2025/02/20/ai-is-eroding-code-quality-states-new-in-depth-report/)
- **Как спросишь, так и ответит.** Уровень запроса и уровень ответа Claude коррелируют с r = 0,93 (117 стран,
  данные агрегированы по странам). Вывод Anthropic: то, как человек формулирует запрос, определяет, насколько
  эффективен AI. [Anthropic Economic Index, Jan 2026](https://www.anthropic.com/research/anthropic-economic-index-january-2026-report)
- **Структурированная архитектура выравнивает модели.** 90 прогонов, 6 моделей. Контракты на TypeScript
  и OpenAPI сильнее всего помогают слабым моделям, сильным формат спецификации почти не важен.
  [Canedo, 2026](https://arxiv.org/abs/2608.21747)

- **Ощущения обманывают.** В RCT METR (2025) участвовали 16 опытных разработчиков, решивших 246 задач в своих
  репозиториях. С AI они работали на 19% медленнее, хотя считали, что на 20% быстрее. В повторном исследовании
  2026 года появились признаки ускорения, но METR сам называет оценку ненадёжной: многие разработчики
  отказываются работать без AI. [METR 2025](https://x.com/METR_Evals/status/1943360399220388093),
  [обновление 2026](https://metr.org/blog/2026-02-24-uplift-update/)
- **Узкое место — ревью.** Faros AI собрал телеметрию 10 000+ разработчиков из 1255 команд. При высоком
  использовании AI задач закрывается на 21% больше, а PR — на 98% больше. При этом время ревью растёт на 91%,
  а размер PR — на 154%. На уровне компании эффекта почти нет.
  [Faros AI, 2025](https://www.faros.ai/blog/key-takeaways-from-the-dora-report-2025)
- **Прирост зависит от задачи.** По данным около 100 000 разработчиков из 600+ компаний средний прирост
  составляет 15–20%. На простых задачах в новом проекте — 30–35%, на сложных в старом коде — 5–10%.
  [Stanford, Denisov-Blanch](https://www.ai.engineer/talks/tbDDYKRFjhk-ai-developer-productivity)
- **Горизонт задач.** METR оценивает длину задач, которые агент доводит до конца сам хотя бы в половине
  случаев. Длину задачи меряют временем, которое на неё тратит человек. В 2019–2025 годах этот горизонт
  удваивался каждые ~7 месяцев. Модели начала 2025 года справлялись с задачами примерно на час работы человека.
  [METR, 2025](https://metr.org/research/)
- **Доверие.** В опросе Stack Overflow 2025 участвовали 49 000 разработчиков. 66% раздражают «почти
  правильные» решения от AI, точности AI доверяют около трети.
  [Stack Overflow 2025](https://stackoverflow.blog/2025/07/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here/)
- **Практика Anthropic.** В опросе 132 инженеров Claude используется в 59% работы, самооценка прироста
  продуктивности — +50%. 27% задач без AI не делались бы вовсе.
  [Anthropic, 2025](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic)
- **Рекомендации Anthropic.** Рекомендуемый цикл — «исследовать → спланировать → написать код →
  закоммитить». Без первых двух шагов модель сразу бросается писать код. Контекст стоит чаще очищать:
  качество падает по мере его заполнения.
  [Claude Code best practices](https://www.anthropic.com/engineering/claude-code-best-practices)
